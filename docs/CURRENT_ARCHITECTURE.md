# GenoGuide — Current Architecture Audit

**Audit date:** 2026-08-22
**Auditor scope:** entire repository at commit `76fc3c8` (Initial commit - GenoGuide)
**Verdict:** a polished hackathon demo with a real-but-small ML component, a real
deterministic ACMG subset, and a real hash-chained local ledger — built on a
fully synthetic dataset. Suitable as a UI/API contract prototype; not yet a
research system.

## 2. Backend architecture

- Single FastAPI module (`main.py`) with a lifespan hook that (a) creates the
  ledger table, (b) trains-or-loads XGBoost, (c) seeds consent + interpretation
  blocks for 3 synthetic patients.
- **Legacy API surface (consumed by the existing frontend — must be preserved):**

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/status` | component readiness, mode, versions |
| GET | `/api/stats` | overview stat cards |
| GET | `/api/variants` | list of 120 demo variants |
| GET | `/api/variants/{id}` | single variant detail |
| POST | `/api/analyze` | full pipeline for one variant; appends ledger block |
| GET | `/api/patients` / `/api/patients/{id}` | synthetic patients |
| GET | `/api/patients/{id}/context` | per-variant relevance + considerations |
| GET | `/api/graph/{patient_id}` | knowledge-graph nodes/edges |
| GET | `/api/provenance/audit` | ledger blocks + contract metadata |
| POST | `/api/provenance/verify` | genuine chain recomputation |
| GET/POST | `/api/provenance/consent/*` | consent record/verify/revoke |

- Persistence: SQLite (`backend/app/genoguide.db`) for the ledger only.
  Variants and patients are Python constants (in-memory).

## 3. Existing ML code (`ml.py`)

- **XGBoost** `multi:softprob`, 5 classes, 150 rounds × 5 = 750 trees, depth 4,
  11 hand-crafted features. Trained at first startup on **3,000 synthetic rows**
  generated by the same class-conditioned sampler that generates the demo
  cohort (different seed). Holdout accuracy ≈ 0.94 — an **in-distribution,
  synthetic-to-synthetic number with no clinical meaning**.
- **ESM-2**: `esm2_t6_8M_UR50D` named everywhere, but in default `DEMO_MODE`
  the model is **never loaded**; "embeddings" are deterministic seeded vectors
  and the Δ-score is a stored per-variant constant. A real fair-esm inference
  path exists behind `GENOGUIDE_MODE=live`, operating on **synthetic 41-aa
  sequence windows** (not real transcripts).
- 8 showcase variants return **hard-coded curated probabilities** in demo mode
  (honestly labeled `precomputed-demo` in API responses).

## 4. Existing ACMG implementation (`acmg.py`)

- 13 of 28 criteria: PVS1, PS1, PS3, PM1, PM2, PM4, PP1, PP3, BA1, BS1, BS3,
  BP4, BP7. Pure functions over structured annotations; combining rules follow
  Richards et al. 2015 with one liberal extension (a single BS criterion alone
  → Likely Benign).
- Global hard-coded thresholds (PM2 < 1e-4, BA1 > 0.05, REVEL ≥ 0.7 …); no
  gene-specific/ClinGen specifications, no PVS1 decision tree, no rule
  versioning per criterion, no evidence-source provenance beyond a label string.
- Reconciliation: 3-bucket concordance (P/LP vs VUS vs B/LB); ACMG output is
  always authoritative — this invariant is real and enforced in `main.py`.

## 5. Dataset implementation (`dataset.py`)

- 8 curated showcase variants (evidence fields modeled on public knowledge,
  simplified) + 112 seeded synthetic cohort variants with a `_target_hint`
  used to generate XGBoost training data — i.e., **the label generator and the
  feature generator are the same process** (by design, for the demo).
- 3 synthetic patients with narrative genome-funnel constants
  (24,812 → 1,426 → 84 → 7 etc.).

## 6. Provenance ledger (`provenance.py`)

- Append-only SQLite table; each block: canonical-JSON payload → SHA-256
  payload hash → block hash over `index|prev|contract|fn|subject|payload|ts`;
  tx id derived from block hash. Verification genuinely recomputes the chain.
- Contract-style functions: recordConsent / verifyConsent / revokeConsent /
  recordInterpretation / verifyInterpretation / getAuditTrail.
- Records model_version + evidence_version strings. **Missing:** input hashes,
  annotation/knowledge/rule versions, operator, evidence snapshots,
  reproducibility metadata. Consent state is recorded but **not enforced** by
  the analyze endpoint. `patient_hash` is an unsalted SHA-256 of a short ID.

## 7. Dependencies

- Backend: fastapi, uvicorn, xgboost, scikit-learn, numpy, pydantic
  (+ optional torch/fair-esm). Python 3.14 venv at `backend/.venv`.
- Frontend: Next 16, React 19, Tailwind 4, framer-motion, three/R3F, recharts,
  lucide (READ-ONLY).
